# Domain docs

This workspace uses a single-context layout: [GLOSSARY.md](../../GLOSSARY.md) at the root and ADRs in `docs/adr/` when a decision calls for one.

Before exploring an area, read the glossary and relevant ADRs if present. Proceed when they do not exist; domain-modeling creates them as terms or decisions are resolved.

Use glossary terms in issue titles, proposals, hypotheses, and tests. Reconsider unfamiliar terms or note a genuine gap for domain-modeling. Surface conflicts with existing ADRs explicitly.
