# Architecture Decision Records

Architecture Decision Records (ADRs) capture significant technical decisions, why they were made, and the constraints future work must preserve.

ADRs do not replace implementation docs, product specs, or operating guides. They record decisions that should remain understandable after the original discussion is gone.

## Status

Use one of:

- Proposed
- Accepted
- Superseded
- Deprecated

Accepted ADRs should not be silently rewritten when the decision changes. Add a new ADR that supersedes the old one and link both records.

## Template

```md
# ADR-XXXX: Decision title

Status: Accepted
Date: YYYY-MM-DD

## Context

## Decision

## Consequences

## References
```

Keep ADRs concise and evidence-based.
